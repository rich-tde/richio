# Contributing & building the docs

## Building the documentation

The site is built with [MkDocs](https://www.mkdocs.org/) and the
[mkdocstrings](https://mkdocstrings.github.io/) plugin (for the auto-generated
[API reference](../api/data.md)).

From the repository root:

```bash
# 1. install richio (so the API pages resolve) and the docs toolchain
pip install -e .
pip install -r docs/requirements.txt

# 2. build / serve from the docs directory
cd docs
mkdocs serve            # live preview at http://127.0.0.1:8000
mkdocs build --strict   # one-off build into docs/site (fails on broken links)
```

`mkdocs build` regenerates `docs/site/`; that directory is build output (it is
git-ignored, so there is no need to edit or commit it). `--strict` turns warnings (broken
links, missing pages) into errors, so it is the recommended way to catch
mistakes and could gate CI.

!!! note "Optional-module API pages"
    The API reference is generated by static analysis (griffe), so the
    `richio.render` and `richio.shockfinder` pages build even without their
    optional dependencies (`yt`, `numba`) installed. Install those
    extras if you want to *run* the examples on those pages.

## Project layout

```
richio/
  data.py          # load() + Snapshot classes (core I/O & analysis)
  units.py         # RICH code unit system (unyt)
  config.py        # FIELD_REGISTRY (field names, aliases, units)
  plots.py         # SnapshotPlotter (snap.plots) + scalar_map
  render/          # optional: 3-D volume rendering (yt)
  shockfinder/     # optional: shock detection (SciPy + optional numba)
docs/              # this documentation site
```

## Where things are documented

When you add or change a field, edit **`richio/config.py`** (`FIELD_REGISTRY`)
only. It is the single source of truth for names, aliases, and units, and both
the library and these docs read from it.
